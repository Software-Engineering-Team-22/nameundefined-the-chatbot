## Non-Functional Requirements

- Response time must be relatively fast, the chatbot can’t think for hours for a 2 line response.

- The page that the chatbot will be on also has to load relatively fast.

- It musn’t use a lot of ram or cpu.
  - One because of the usage of this chatbot on a mobile device.
  - Two because it would just be inefficient

- It must be able to handle a lot of different user input, both by allowing the user to basically spam the bot, as well as there being no problem with a lot of users connecting to the chatbot.

- The bot if to be put in a museum, it must not break or need maintenance and must have a perfect uptime.

- The chatbot must be consistent, it shouldn’t start hallucinating random historical facts.

- It doesn't need a lot of security however it would be pretty bad if anyone could change what the bot is saying to whatever they want.

- It must be easy and pretty intuitive to use as the people who will use this might come from a wide variety of technological backgrounds.

- If there is a problem, it has to be easily identifiable and fixed quickly.

- It must also be accessible and available on any device that a user might use to interact with our chatbot.

- If the chatbot is for personal use or for a museum this might change. Private chats with our bot must obviously be private, if it is for public use in an exhibit that is a little less possible because it's a public place and a public tool.

- If we ever need to or want to upgrade or change something about our bot it must be hassle free and we need to have a way to do it seamlessly.

- The chatbot must adhere to industry-specific regulations and standards, ensuring legal compliance in data handling, accessibility, and operational practice.
